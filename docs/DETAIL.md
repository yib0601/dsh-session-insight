# 每轮费用（官方价）与用量总览

## 三个界面入口概览

| 入口 | 在哪 | 内容 |
|---|---|---|
| 逐轮徽章 | 每条回复的**动作行**（复制 / 点赞 / `用量 … tok` / 时间之后） | 本轮金额，如 `¥0.0182` |
| 会话累计药丸 | 输入框下方状态栏（`1 轮 109 步` / `21.3M tok` 那一行） | 本会话累计金额；设了预算时是 `花费 / 预算` |
| 上下文 / 用量总览 | 会话内：会话「上下文」页签、右侧栏 Context 页签、`/context` 命令弹窗；跨会话：侧栏脚「用量总览」 | KPI 磁贴 + 卡片 |

三个入口的金额同源同口径：都优先读本插件 Host 侧的 `tcTimeline` 请求日志，**逐请求**按「该请求实际用的模型 + 它发生时刻的高峰/空闲档」计价。

## 逐轮徽章

徽章与用量、时间同排，只显示金额本身；悬浮 `title` 写「本轮消耗」，点击展开明细浮层（沿用 DSH 统计卡的皮肤）：

- 标题行：图标 + 「本轮消耗」+ 金额
- 明细：模型 / 缓存命中率 / 四个 token 桶的**数量 × 官方单价 = 该桶金额** / 计费时段
- 尾注：计价口径（按会话日志逐请求）、官方价目表链接、估算声明

按 **Esc** 或点击外部收起；带键盘焦点环与 `aria-expanded` / `aria-controls`。模型没产出最终回复、因而没有动作行的轮次，徽章回退成该轮末尾独立一行。

## 会话累计药丸

- 只有金额（`¥0.0549`），`title`/`aria-label` 给出轮次与用量。
- 明细浮层：缓存命中率、已计价轮次、总用量、预算与剩余额度（设了预算时）、计价口径。
- **会话预算**（设置 → 费用）设成非 0 后：药丸变成 `¥0.72 / ¥1.00` 并带一条细进度条；超支后金额与进度条转红（`--dsw-alias-state-error-primary`），明细里给出「已超出 ¥x」。

## 上下文页签（会话内）

顶部一条 KPI 磁贴带：轮次 / 步骤 / 请求 / 计费 tokens / 估算费用 / 缓存命中；设了预算时下面多一条预算带（花费 / 预算、剩余、进度条）。卡片按 12 列栅格排布：

1. **上下文统计** —— 一条横向计数带：轮次 / 步骤 / 用户输入 / 助手消息 / 技能加载 / 工具调用总数；下面并排两块分布：**工具调用分布**（每个工具被调用了多少次，取前 8 名）与**命令程序分布**（`python3` / `grep` / `sed` … 各跑了多少次）。程序名从命令行首 token 提取，自动跳过 `sudo` / `env` / `FOO=1` / `cd <dir> &&` 这类包装，取真正的可执行名。
2. **当前上下文构成** —— 系统提示词 / 工具定义 / 消息与工具结果三段堆叠条（按已用量归一，小占比也看得见）+ 每段数值与占比 + 上下文窗口占用细条 + 估算口径说明。
3. **上下文明细** —— 「当前上下文构成」只给三段总数（系统提示词 / 工具定义 / 消息与工具结果），这张卡把每段拆到条目，并**点开就能读正文**。视觉上分四层，每层只回答一个问题：
   - **第一层｜整个窗口**：一条带底的摘要横条 = 「系统提示词 / 工具定义 / 消息与工具结果」堆叠条 + 图例（每项带 tokens 与占比）。先看清 142,534 是怎么分成 5.7% / 12.0% / 82.3% 的，再往下挑页签
   - **第二层｜页签**：系统提示词（默认）/ 工具定义 / 占用最大 —— 导航用下划线页签（选中 = 主色下划线 + 加粗主色文字），与右侧「按大小 / 按名称」那种浅色分段控件在形状上就分开：一个是「看哪一桶」，一个是「怎么排」。每个页签右侧是**条目计数**徽标，所以「16 个分区 / 86 条工具 / 24 条消息」不用打开就知道
   - **第三层｜本页签的量级**：`8,104 tok · 5.7% 占上下文 · 16 个分区`，右侧是搜索框与「按大小 / 按名称」（弱化的浅色分段控件，不与页签抢视线）。这一行给出每行**占比的分母**，行内的百分比才有意义；筛过之后这里变成「显示 3 / 16」。只在「占用最大」页签下再多一条**消息构成**（用户输入 / 助手思考 / 工具参数 / 工具结果 … 的细分条），因为那是消息桶自己的拆分
   - **第四层｜行**：`▸ 名称 │ 一句话摘要 │ 量级条 │ tokens │ 占比`。左侧名称是主级（`label-primary`），摘要是一行弱化提示（去掉 banner 装饰线，直接说这一条里是什么），量级条相对本页签最大行、占比相对本页签总量，两列数字上方有列头（条目 / tokens / 占比）——不靠悬停也知道右边两个数是什么
   - **最大的一行**（列表头名）保持满强度色条与半粗数字，其余行条降到 42% 透明度：列表有「头」，不是一片等高柱子
   - **点一行展开**：整行抬成带色底的容器（左侧 2px 强调轨），正文上方是一排标签（tokens / 占本页签 / 字符数 / 轮次·步 / 截断），下面是等宽可滚动的正文框。同一页签只开一条，40 个分区不会同时铺开
   - 工具条：搜索框（**名称、描述与正文一起搜**，所以「哪一节提到 X」能直接筛出来）+ 按大小 / 按名称排序
   - **窄了就降级**：卡片同时出现在整宽页签和约 380px 的右侧栏，所以断点用容器查询（`container-type: inline-size`）而不是视口——≤820px 先去掉摘要列，≤460px 再去掉量级条并把摘要横条改为上下堆叠，页签平分整行
   - 正文有上限：单段正文 12K 字符、单条工具 schema 6K 字符，且**整卡按总预算分配**（系统分区 64K、工具 80K，按体积从大到小给），超出的条目置空并标「正文已截断」，卡上明示——不留一个看起来有、点开是空的坑。当前这条 2000+ 事件会话实测：16 个分区 + 86 条工具全部带正文，整份投影 146KB
   - 三项合计与 DSH 内置 `contextBreakdown` **逐项相等**（同一会话日志重放实测 `8104 / 17129 / 356622` 完全一致），所以这张卡不是另一套口径，只是把同一笔账拆开；分区估价是纯文本密度（约 4 字符 ≈ 1 token），不含角色开销，卡脚写明
   - 压缩（compact / prune）之后按影子价回撤对应的行；若被影子化的节点已出保留窗口，按影子价从最大桶扣除并置「近似」标记，不假装精确

4. **Token 统计** —— 环形图（占比一眼可见）+ 四桶堆叠条 + 每桶「数量 · 占比 · 金额」+ 合计；卡片头给缓存命中率。
5. **费用（官方刊例价）** —— 主金额 + 另一种币种对照 chip + 计费时段 chip（高峰 / 空闲 / 混合）+ 按桶的费用构成条与金额 + 请求数 / 未知价请求数 + 估算声明。
6. **上下文趋势** —— 面积 sparkline，可在 **Tokens / 费用 / 缓存命中** 三档间切换；标注峰值与最新值。
7. **按模型花费** —— 每个模型的花费条、金额、占比，悬浮给 tokens 与请求数。
8. **时序统计** —— 模型耗时 / 工具耗时 / 首字延迟 / 解码速度 / 解码耗时。
9. **文件活动** —— 每行一个被操作的文件：路径、`+新增 / −删除` 行数估算、`R` / `W` / `S` 计数 chip。顶部可按**读取 / 写入 / 搜索**筛选、按路径搜索；点一行展开**操作日志**（最近 6 次操作，带时间、类型、轮次与行数增减）。行数来自 `edit` / `write` 的文本与 `apply_patch` 每个文件段落里的 `+` / `-` 行。
10. **命令执行** —— 程序分布 chip（可点选筛选）+ 状态分段控件（全部 / 成功 / 失败 / 进行中）+ 搜索框；下面是流水：程序名、命令行首行、墙钟耗时与状态 chip（`成功` / `失败` / `进行中`）。
11. **上下文事件** —— 压缩 / 剪枝 / 注入 / 模型切换 / 模式切换，带类型 chip、名称、tokens 与轮次；每个类型 chip 显示该类型的全量计数，点一下只看这一类。
12. **Agent 网络** —— 子会话列表与运行状态 chip。
13. **上下文浏览器** —— 逐请求表：轮/步、模型、tokens、费用；可**筛选**（模型 / 提供方 / 轮次 / `轮/步`）、按**时间 / 费用 / Tokens 排序**、**复制 CSV**（成功显示「已复制」，失败显示「复制失败」）；点行展开 provider、模型、四个桶、缓存命中率、计费时段、时间，以及**请求内容**：用户消息、助手「思考 / 回答 / 工具调用（含参数）」、该步产生的工具结果，每条默认 300 字预览、点「展开」看全文（上限 2400 字）。内容取自页面自己持有的聊天快照（`legacy.nodes`），不联网、不落盘、不写会话日志。长会话不再被截断：每页 60 行，底部「显示更多（还有 N 条）」继续加载，换筛选或排序自动回到第一页；卡片头始终写「显示 X / Y」。

## `/context` 命令

输入 `/context` 回车（或从命令候选里选）弹出居中弹窗：KPI 磁贴 + 构成卡 + 费用卡 + 按模型花费卡，Esc 或点遮罩关闭。打开弹窗会顺手收起其它浮层（例如底部费用明细）。

## Agent 家族卡（上下文页内）

「上下文」页内的一张卡，不单开页签：同一个 Agent 家族一行一人。

- **Agent 网络**：父级、当前、子级、孙级各一行，带角色 chip、运行中标记、该会话自己的 tokens 与官方价估算费用；卡头写家族总费用
- **家族事件** 由同页的「上下文事件」卡承担（注入 / 压缩 / 模型切换 / 模式），不重复第二份
- 家族成员来自会话树（`sessions.byId` 的 `parentId`），费用按每个成员自己会话日志的价目表估算；**任务板**数据不在本插件的读模型内，卡脚有一行说明而不是空卡片冒充

同一个视图也挂在右侧栏 Context 页签下。

## 用量总览（跨会话）

侧栏脚「用量总览」按钮打开全屏总览：

- 标题栏**时间范围**：今天 / 近 7 天 / 近 30 天，作用于 KPI、柱图、模型榜、排行与会话卡（热力图固定近 12 周，否则 1 天的范围会把它抹掉）
- KPI 磁贴：会话数 / 计费 tokens / 估算费用 / 缓存命中。「会话」数的是**所选范围内有用量**的会话，第二行小字给出工作区里的会话总数（只有读进投影的会话才有日志可算，两者可以不等）
- **近 7 日用量**：Tokens 柱图 + 费用柱图。每根柱子都带**数值标签**（`52M` / `¥1.52`），柱高线性归一时小额日只剩 2px 也读得出数；本周合计在中间一行
- **活跃热力图**：近 12 周，周一为列首，空格补位；每格 `title` 给日期、tokens 与费用
- **跨会话模型花费**：所有会话按模型聚合的花费榜
- **会话**：可搜索（标题）、按费用 / Tokens / 最近排序的会话卡片，点开直达该会话；同样每页 60 个 +「显示更多」
- **排行**：工具调用排行 / 命令程序排行 / 技能加载，按所选范围聚合各会话日志里的名称计数（Host 侧按天折叠并封顶，Client 只做排序）。Host 是旧模块世代时这三张卡会写明「统计字段要等 DSH 重启后由 Host 折叠出来」，而不是假装没有数据

仪表盘的历史金额**按每笔请求当时的计费时段**计价（Host 在折叠时就按请求时间分成 `peak` / `offPeak` 两个桶），不会因为「打开仪表盘时是高峰」而把整段历史按高峰价重算——DeepSeek 两档差一倍，这个差别在仪表盘上就是成倍的。把偏好里的计费时段定成高峰 / 空闲时，全表统一按该档算（与徽章、药丸一致）。

## 订阅额度（侧栏脚）

侧栏脚「用量总览」是一条两行卡片，直接显示**当前正在用的那个订阅**还剩多少、还够用多少天；点按按钮同时强刷额度并打开总览：

- **跟随供应商，只看 provider**：判定源用请求里记录的 **provider id**（`tcTimeline` 的 `current` / `requests[*]`），不看模型名——同一个 `deepseek-v4.1-flash` 既可能由 DeepSeek 官方平台服务，也可能由 OpenCode 服务，还可能由自建网关转发，只有 provider 能说明**是谁的订阅在扣**。映射只有两条：`opencode` / `opencode-go` / `opencode-go-v41` → OpenCode Go；`deepseek` / `deepseek-account` / `deepseek-official` → DeepSeek。provider 完全缺失时只认模型名里的 `OpenCode` 字样。
- **自建网关没有额度，就不显示额度**：`ai-router` 这类自建网关是多后端的转发层（后端可能是 oc-go / oc-zen / openrouter / gemini…），它按**上游密钥**分别计费，网关自己的密钥 `quota_requests` / `quota_tokens` 通常为 null，`/health` 描述的也只是后端状态而不是调用方的余量——因此**没有任何诚实的数字可显示**。这类 provider 归入 `NO_SOURCE`：卡片不显示金额、不显示百分比、不算倒计时、**一次额度请求都不发**，只写一行「此供应商无额度可查」，悬浮补一句为什么。不借用 OpenCode 的窗口来顶替：网关可能把请求转给任意后端，而那些窗口属于另一把密钥。
- **切模型立刻生效**：`tcTimeline` 的 `current` 由 `model/selection` 写入并带自身时间戳，所以**改完模型不必先发一条消息**额度就跟着换；比较时 `current` 与各会话 `requests` 末尾按时间排，谁新听谁的，旧切换不会压过别处更新的请求。
- **无源时留白**：拿不到 provider 也没有上次记忆时，卡片**不显示任何数字**（状态 `idle`，`refresh` 直接返回，不读任何源）。这是刻意的——以前路由参数默认 `deepseek`，刷新页面会在会话自己的路由还没到达前先画一次 DeepSeek 钱包，OpenCode 订阅的账户就看到了「DeepSeek 官方额度」。
- **两种「不显示」要分清**：`idle` = 还不知道（等会话路由），`nostore` = 已经知道，且该 provider 本来就没有额度。前者悬浮只有标题，后者给出原因；`NO_SOURCE` 也会被记忆，所以新开空会话仍然不会回落到别的套餐。
- **记住上次的源**：认出的源写进 `localStorage` 的 `dsh-turn-cost:quota-source`，新开空会话或刷新时先按它显示，等会话自己的路由到达再覆盖。
- **第一行**：`用量总览` + 右侧倒计时徽标（`剩 12 天`）。倒计时取**最长额度窗口的重置时刻**——OpenCode Go 的月窗口重置即订阅周期结束，官方 `usage` 接口除这三个窗口的重置时间外不给到期字段，所以周期长度由此推出；不满 1 天给小时、不满 1 小时给分钟，过点写「已到期」。≤7 天转黄、≤3 天转红。悬浮徽标给出确定的日期时刻（如「订阅周期 12-02 23:30 结束（剩 12 天）」）。
- **第二行（OpenCode Go）**：5 小时 / 周 / 月三条**微型计量条**——标签 + 百分比 + 3px 轨道，填充按百分比给长度，≥70% 转黄、≥90% 转红，一眼看出哪档先见底。整卡悬浮给三档全称、百分比、**北京时间重置时间与各档自己的倒计时**（如「本周：已用 37%，11-23 08:00 重置（剩 2 天）」）。侧栏折叠成 36px 导轨时整卡收成一枚小方块：最紧那档的百分比 + 紧凑倒计时（`54%` / `12天`）。
- **仪表盘磁贴**：标题写「OpenCode Go 额度」，主数字是最紧的那档（`月 54%`），副行给倒计时与读取时刻（`剩 12 天 · 23:21 更新`）；三档全量在悬浮明细里。
- **DeepSeek**：官方 `GET https://api.deepseek.com/user/balance`，取每币种 `total_balance` 并保留 `topped_up_balance` / `granted_balance` 拆项。第二行是 `¥19.75`（无周期可算，只有钱包）；悬浮给充值 / 赠送拆项；磁贴同源。
- **先画上次读数，再静默刷新**：每次读数成功都按源写进 `localStorage` 的 `dsh-turn-cost:quota-cache`（`{source:{at,snapshot}}`），下次加载（刷新页面、chunk 重新加载、开新会话）先按它把上次的数字画上去，**不发「读取中…」**，同时在后台静默读一次；只有这个源**从来没有过读数**时才显示「读取中…」。缓存的有效期取 5 小时（最短的 5 小时窗口一个周期内必然已重置，更久的百分比描述的是已经结束的周期），并且**任一窗口的重置时刻已过就整条作废**——把上个周期的 47% 画到新周期上比转圈更误导。带过来／刷新失败的数字会降透明度并在悬浮里注明「显示的是上次成功读数，正在后台重试」，不再整卡变成「额度不可用」；`failed` / `loading` / `nostore` / 零余额一律不写缓存。
- **什么时候再读**：客户端每 5 分钟轮询一次；另外标签页从后台回到前台（`visibilitychange` → `visible`）和网络恢复（`online`）各补读一次，避免挂机几小时后看到的还是几小时前的数。这次补读不带 `force`，仍在 Host 的 5 分钟新鲜期内就直接用缓存，不打厂商接口。
- **数据流**：Client 只请求同源路由 `GET /dsh-turn-cost/quota?source=<id>`（每 5 分钟一次，点按带 `force=1`）。Host 的 `host/quota.js` 才持有密钥（`credentials` 里的 `DEEPSEEK_API_KEY` / `OPENCODE_GO_API_KEY`，每次读取时解析，不缓存）、发官方请求（OpenCode 每次请求现造 `x-opencode-session` / `x-opencode-request`，12s 超时）、按源缓存 5 分钟。**密钥与官方原始 payload 都不进页面**。
- **异常分支**：读失败（网络、超时、非 2xx）→「额度不可用」；Host 未配置该源密钥 →「未配置密钥」；余额/窗口为 0 →「零余额」。三者都不伪装成 0 消耗。失败不写缓存，下一次轮询／点按会重试；缓存里的上一次成功值继续服务非强制读。
- **无源分支**：既没有会话路由也没有记忆 → 卡片只有标题与按钮，不显示金额、不显示百分比、不发请求。
- **失败是安全的**：Host 没有 `webServer` 或 `credentials` 时不会注册路由，按钮退回普通样式（首读失败即静默），费用与上下文功能完全不受影响。未知 `source` 参数由 Host 直接 400，不会悄悄给成默认源。

## 偏好设置

`设置 → 费用`（插件自有页面，带 ¥ 图标）分组呈现：

- **显示**：逐轮费用徽章（开关）、底部会话累计（开关）
- **计价**：金额币种（人民币 / 美元分段控件）、DeepSeek 计费时段（自动按北京时间 / 按高峰 / 按空闲）
- **预算**：会话预算（0 = 不设上限，正数 = 显示 花费/预算 并在超支转红）

偏好存在浏览器 `localStorage`（键 `dsh-turn-cost:prefs`），不写 Host 配置，也不影响其他客户端。切换币种立即作用于所有金额界面。

## 计算口径

- 用量直接取 DSH 自带的 `deriveTurnTokenUsage()` 结果（`turn-tail` 节点的 `tokenUsage`），包含重试与失败 attempt，精确到 token；本插件不重算会话日志。
- 四个桶分别按各自的官方单价计价；每桶金额由 `桶数量 × 显示币种单价` 得出，徽章明细、Token 统计、费用构成三处用的是同一份数。
- **DeepSeek 高峰/空闲**：官方规定北京时间周一至周五 09:00–12:00、14:00–18:00 为高峰（不含中国法定节假日），空闲价为高峰价一半。会话内的每一笔请求按它自己的时间判档（徽章、药丸、费用卡、逐请求浏览器都如此）；仪表盘是跨会话的按天聚合、请求时间不再保留，所以 Host 在折叠时就把每笔请求分进 `peakBuckets` / `offPeakBuckets`，仪表盘按桶分别计价，历史金额不会被「现在几点」改写。`HOLIDAYS_UTC8`（Host 侧同名常量 `BEIJING_HOLIDAYS`）可按需补充，两处需同时改。
- 一輪若用了多个模型，聚合用量无法按模型拆分：按首个模型计价并用 `≈` 标记。
- 部分 attempt 未上报缓存桶时，未归属的提示词按缓存命中单价计（保守下界），同样用 `≈` 标记。
- 经由网关（`ai-router` / `opencode-go` 等）调用时，官方模型常以版本名出现（如 `deepseek-v4.1-flash`）。插件把官方文档明确认定为同一模型的别名映射到官方价格行；详情里会说明这是**按官方刊例价估算，非实际扣费**。
- 提供方明确标注免费的模型显示 `¥0 · 免费`；价格表未收录的模型显示「价格未知」，**不会**按 `0` 计。会话累计会注明有多少请求未计入。
- 币种只影响显示：`usd` / `cny` 两份金额始终同时保留。

## 视觉约定

所有界面只用宿主语义 token（`--dsw-alias-*` / `--dsw-font-*` / `--dsw-radius-*` / `--dsw-elevation-*`），不写死颜色，浅色与深色主题都成立。数据色用宿主的 `--dsw-alias-chart-system / chart-tools / chart-messages` 与 `state-*`。分段控件的选中态用 `--dsw-alias-button-primary-fill` + `--dsw-alias-label-primary-foreground` —— 不要用 `--dsw-alias-brand-primary`（深色主题里它是近白色 `#f9fafb`，会造成白底白字）。

## 不包含

- 子 Agent 会话的费用（只统计当前会话的轮次；仪表盘按会话聚合时也只读各会话自己的日志）。
- 联网搜索 / 文件解析 / OCR / TTS 等按次计费项。
- Batch / Flex / Priority 等非标准计费档；一律按 Standard 同步档。
- 网关/转售商（OpenRouter、Groq 等）的价格：没有单一第一方刊例价。

## 价格过期怎么办

官方价目会变。更新 `client.js` 顶部 `OFFICIAL` 表中对应模型的数字，并同步修改 `docs/PRICING.md` 的核对日期与徽章明细里的 `date`（`client.js` 中 `t('source', { date: ... })`）。修改后刷新页面即可生效（无需重启 DSH）。

> 改了 `client.context.js` 记得 `touch client.js`：Host 只监听入口文件，静态包按 rev（mtime）作 URL，rev 不变浏览器会继续用 `immutable` 缓存的旧 chunk。
