# 每轮费用（官方价）与用量总览

## 三个界面入口概览

| 入口 | 在哪 | 内容 |
|---|---|---|
| 逐轮徽章 | 每条回复的**动作行**（复制 / 点赞 / `用量 … tok` / 时间之后） | 本轮金额，如 `¥0.0182` |
| 会话累计药丸 | 输入框下方状态栏（`1 轮 109 步` / `21.3M tok` 那一行） | 本会话累计金额；设了预算时是 `花费 / 预算` |
| 上下文 / 用量总览 | 会话内：会话「上下文」页签、右侧栏 Context 页签、`/context` 命令弹窗；跨会话：侧栏脚「用量总览」 | KPI 磁贴 + 卡片 |

三个入口的金额同源同口径：都优先读本插件 Host 侧的 `tcTimeline` 请求日志，**逐请求**按「该请求实际用的模型 + 它发生时刻的高峰/空闲档」计价。

## 逐轮徽章

徽章与用量、时间同排，只显示金额本身；悬浮 `title` 写「本轮消耗」，点击展开明细浮层（沿用 DSH 统计卡的皮肤）：

- 标题行：图标 + 「本轮消耗」+ 金额
- 明细：模型 / 缓存命中率 / 四个 token 桶的**数量 × 官方单价 = 该桶金额** / 计费时段
- 尾注：计价口径（按会话日志逐请求）、官方价目表链接、估算声明

按 **Esc** 或点击外部收起；带键盘焦点环与 `aria-expanded` / `aria-controls`。模型没产出最终回复、因而没有动作行的轮次，徽章回退成该轮末尾独立一行。

## 会话累计药丸

- 只有金额（`¥0.0549`），`title`/`aria-label` 给出轮次与用量。
- 明细浮层：缓存命中率、已计价轮次、总用量、预算与剩余额度（设了预算时）、计价口径。
- **会话预算**（设置 → 费用）设成非 0 后：药丸变成 `¥0.72 / ¥1.00` 并带一条细进度条；超支后金额与进度条转红（`--dsw-alias-state-error-primary`），明细里给出「已超出 ¥x」。

## 上下文页签（会话内）

顶部一条 KPI 磁贴带：轮次 / 步骤 / 请求 / 计费 tokens / 估算费用 / 缓存命中；设了预算时下面多一条预算带（花费 / 预算、剩余、进度条）。卡片按 12 列栅格排布：

1. **上下文统计** —— 一条横向计数带：轮次 / 步骤 / 用户输入 / 助手消息 / 技能加载 / 工具调用总数；下面并排两块分布：**工具调用分布**（每个工具被调用了多少次，取前 8 名）与**命令程序分布**（`python3` / `grep` / `sed` … 各跑了多少次）。程序名从命令行首 token 提取，自动跳过 `sudo` / `env` / `FOO=1` / `cd <dir> &&` 这类包装，取真正的可执行名。
2. **当前上下文构成** —— 系统提示词 / 工具定义 / 消息与工具结果三段堆叠条（按已用量归一，小占比也看得见）+ 每段数值与占比 + 上下文窗口占用细条 + 估算口径说明。
3. **上下文明细** —— 「当前上下文构成」只给三段总数（系统提示词 / 工具定义 / 消息与工具结果），这张卡把每段拆到条目，并**点开就能读正文**。视觉上分四层，每层只回答一个问题：
   - **第一层｜整个窗口**：一条带底的摘要横条 = 「系统提示词 / 工具定义 / 消息与工具结果」堆叠条 + 图例（每项带 tokens 与占比）。先看清 142,534 是怎么分成 5.7% / 12.0% / 82.3% 的，再往下挑页签
   - **第二层｜页签**：系统提示词（默认）/ 工具定义 / 占用最大 —— 导航用下划线页签（选中 = 主色下划线 + 加粗主色文字），与右侧「按大小 / 按名称」那种浅色分段控件在形状上就分开：一个是「看哪一桶」，一个是「怎么排」。每个页签右侧是**条目计数**徽标，所以「16 个分区 / 86 条工具 / 24 条消息」不用打开就知道
   - **第三层｜本页签的量级**：`8,104 tok · 5.7% 占上下文 · 16 个分区`，右侧是搜索框与「按大小 / 按名称」（弱化的浅色分段控件，不与页签抢视线）。这一行给出每行**占比的分母**，行内的百分比才有意义；筛过之后这里变成「显示 3 / 16」。只在「占用最大」页签下再多一条**消息构成**（用户输入 / 助手思考 / 工具参数 / 工具结果 … 的细分条），因为那是消息桶自己的拆分
   - **第四层｜行**：`▸ 名称 │ 一句话摘要 │ 量级条 │ tokens │ 占比`。左侧名称是主级（`label-primary`），摘要是一行弱化提示（去掉 banner 装饰线，直接说这一条里是什么），量级条相对本页签最大行、占比相对本页签总量，两列数字上方有列头（条目 / tokens / 占比）——不靠悬停也知道右边两个数是什么
   - **最大的一行**（列表头名）保持满强度色条与半粗数字，其余行条降到 42% 透明度：列表有「头」，不是一片等高柱子
   - **点一行展开**：整行抬成带色底的容器（左侧 2px 强调轨），正文上方是一排标签（tokens / 占本页签 / 字符数 / 轮次·步 / 截断），下面是等宽可滚动的正文框。同一页签只开一条，40 个分区不会同时铺开
   - 工具条：搜索框（**名称、描述与正文一起搜**，所以「哪一节提到 X」能直接筛出来）+ 按大小 / 按名称排序
   - **窄了就降级**：卡片同时出现在整宽页签和约 380px 的右侧栏，所以断点用容器查询（`container-type: inline-size`）而不是视口——≤820px 先去掉摘要列，≤460px 再去掉量级条并把摘要横条改为上下堆叠，页签平分整行
   - 正文有上限：单段正文 12K 字符、单条工具 schema 6K 字符，且**整卡按总预算分配**（系统分区 64K、工具 80K，按体积从大到小给），超出的条目置空并标「正文已截断」，卡上明示——不留一个看起来有、点开是空的坑。当前这条 2000+ 事件会话实测：16 个分区 + 86 条工具全部带正文，整份投影 146KB
   - 三项合计与 DSH 内置 `contextBreakdown` **逐项相等**（同一会话日志重放实测 `8104 / 17129 / 356622` 完全一致），所以这张卡不是另一套口径，只是把同一笔账拆开；分区估价是纯文本密度（约 4 字符 ≈ 1 token），不含角色开销，卡脚写明
   - 压缩（compact / prune）之后按影子价回撤对应的行；若被影子化的节点已出保留窗口，按影子价从最大桶扣除并置「近似」标记，不假装精确

4. **Token 统计** —— 环形图（占比一眼可见）+ 四桶堆叠条 + 每桶「数量 · 占比 · 金额」+ 合计；卡片头给缓存命中率。
5. **费用（官方刊例价）** —— 主金额 + 另一种币种对照 chip + 计费时段 chip（高峰 / 空闲 / 混合）+ 按桶的费用构成条与金额 + 请求数 / 未知价请求数 + 估算声明。
6. **上下文趋势** —— 面积 sparkline，可在 **Tokens / 费用 / 缓存命中** 三档间切换；标注峰值与最新值。
7. **按模型花费** —— 每个模型的花费条、金额、占比，悬浮给 tokens 与请求数。
8. **时序统计** —— 模型耗时 / 工具耗时 / 首字延迟 / 解码速度 / 解码耗时。
9. **文件活动** —— 每行一个被操作的文件：路径、`+新增 / −删除` 行数估算、`R` / `W` / `S` 计数 chip。顶部可按**读取 / 写入 / 搜索**筛选、按路径搜索；点一行展开**操作日志**（最近 6 次操作，带时间、类型、轮次与行数增减）。行数来自 `edit` / `write` 的文本与 `apply_patch` 每个文件段落里的 `+` / `-` 行。
10. **命令执行** —— 程序分布 chip（可点选筛选）+ 状态分段控件（全部 / 成功 / 失败 / 进行中）+ 搜索框；下面是流水：程序名、命令行首行、墙钟耗时与状态 chip（`成功` / `失败` / `进行中`）。
11. **上下文事件** —— 压缩 / 剪枝 / 注入 / 模型切换 / 模式切换，带类型 chip、名称、tokens 与轮次；每个类型 chip 显示该类型的全量计数，点一下只看这一类。
12. **Agent 网络** —— 子会话列表与运行状态 chip。
13. **上下文浏览器** —— 逐请求表：轮/步、模型、tokens、费用；可**筛选**（模型 / 提供方 / 轮次 / `轮/步`）、按**时间 / 费用 / Tokens 排序**、**复制 CSV**（成功显示「已复制」，失败显示「复制失败」）；点行展开 provider、模型、四个桶、缓存命中率、计费时段、时间，以及**请求内容**：用户消息、助手「思考 / 回答 / 工具调用（含参数）」、该步产生的工具结果，每条默认 300 字预览、点「展开」看全文（上限 2400 字）。内容取自页面自己持有的聊天快照（`legacy.nodes`），不联网、不落盘、不写会话日志。长会话不再被截断：每页 60 行，底部「显示更多（还有 N 条）」继续加载，换筛选或排序自动回到第一页；卡片头始终写「显示 X / Y」。

右侧栏 Context 页签是同一份视图的第二个挂载点。

## `/context` 命令

输入 `/context` 回车（或从命令候选里选）弹出居中弹窗：KPI 磁贴 + 构成卡 + 费用卡 + 按模型花费卡，Esc 或点遮罩关闭。打开弹窗会顺手收起其它浮层（例如底部费用明细）。

## Agent 家族卡（上下文页内）

「上下文」页内的一张卡，不单开页签：同一个 Agent 家族一行一人。

- **Agent 网络**：父级、当前、子级、孙级各一行，带角色 chip、运行中标记、该会话自己的 tokens 与官方价估算费用；卡头写家族总费用
- **家族事件** 由同页的「上下文事件」卡承担（注入 / 压缩 / 模型切换 / 模式），不重复第二份
- 家族成员来自会话树（`sessions.byId` 的 `parentId`），费用按每个成员自己会话日志的价目表估算；**任务板**数据不在本插件的读模型内，卡脚有一行说明而不是空卡片冒充

同一个视图也挂在右侧栏 Context 页签下。

## 用量总览（跨会话）

侧栏脚「用量总览」按钮打开全屏总览：

- 标题栏**时间范围**：今天 / 近 7 天 / 近 30 天，作用于 KPI、柱图、模型榜、排行与会话卡（热力图固定近 12 周，否则 1 天的范围会把它抹掉）
- KPI 磁贴：会话数 / 计费 tokens / 估算费用 / 缓存命中。「会话」数的是**所选范围内有用量**的会话，第二行小字给出工作区里的会话总数（只有读进投影的会话才有日志可算，两者可以不等）
- **近 7 日用量**：Tokens 柱图 + 费用柱图。每根柱子都带**数值标签**（`52M` / `¥1.52`），柱高线性归一时小额日只剩 2px 也读得出数；本周合计在中间一行
- **活跃热力图**：近 12 周，周一为列首，空格补位；每格 `title` 给日期、tokens 与费用
- **跨会话模型花费**：所有会话按模型聚合的花费榜
- **会话**：可搜索（标题）、按费用 / Tokens / 最近排序的会话卡片，点开直达该会话；同样每页 60 个 +「显示更多」
- **排行**：工具调用排行 / 命令程序排行 / 技能加载，按所选范围聚合各会话日志里的名称计数（Host 侧按天折叠并封顶，Client 只做排序）。Host 是旧模块世代时这三张卡会写明「统计字段要等 DSH 重启后由 Host 折叠出来」，而不是假装没有数据

仪表盘的历史金额**按每笔请求当时的计费时段**计价（Host 在折叠时就按请求时间分成 `peak` / `offPeak` 两个桶），不会因为「打开仪表盘时是高峰」而把整段历史按高峰价重算——DeepSeek 两档差一倍，这个差别在仪表盘上就是成倍的。把偏好里的计费时段定成高峰 / 空闲时，全表统一按该档算（与徽章、药丸一致）。

## 订阅额度（侧栏脚）

侧栏脚「用量总览」是一条两行卡片，直接显示**当前正在用的那个订阅**还剩多少、还够用多少天；点按按钮同时强刷额度并打开总览：

- **跟随供应商，只看 provider**：判定源用请求里记录的 **provider id**（`tcTimeline` 的 `current` / `requests[*]`），不看模型名——同一个 `deepseek-v4.1-flash` 既可能由 DeepSeek 官方平台服务，也可能由 OpenCode 服务，还可能由自建网关转发，只有 provider 能说明**是谁的订阅在扣**。映射：`opencode` / `opencode-go` / `opencode-go-v41` → OpenCode Go；`deepseek` / `deepseek-account` / `deepseek-official` → DeepSeek；`workbuddy` / `workbuddy-shim` → WorkBuddy。provider 完全缺失时只认模型名里的 `OpenCode` 字样。
- **WorkBuddy 是「有额度」的网关，不是 `NO_SOURCE`**：它确实是网关（本机 shim → `copilot.tencent.com`），但那条链只服务**一个账号**，额度是账号级的真事实（积分分包 + 订阅周期）。差别在于令牌只在 shim 手里，所以 Host 读的是 shim 的 `/quota`（`WorkBuddy 额度` 页面承认的正是它），不是腾讯的计费接口。工作端点取 `DSH_TURN_COST_WORKBUDDY_QUOTA_URL`，缺省 `http://127.0.0.1:8898/quota`；生产 shim 只在 Vultr 的回环上，本机用一条常驻 SSH 转发（`workbuddy-shim-tunnel.service`）把它搬到 `127.0.0.1:8898`。凭据 ref `WORKBUDDY_SHIM_TOKEN`（即 shim 的 `WORKBUDDY_SHIM_TOKEN`，不是供应商密钥）。
- **WorkBuddy 的窗口与别人不同**：它没有 rolling/weekly/monthly 三档，而是按**积分包分组**（`套餐积分` / `赠送积分` / `加量包` / `奖励积分`），每档给 `percent`、余量与**重置时刻**。所以窗口标签优先用上游 `label`（供应商自己命名的桶），没有 `label` 才回落到内置词表；`plan`（套餐名 + 到期时刻）是唯一诚实倒计时来源，有它就**不再**「取最长窗口的重置」推周期，也不打印那句推断说明；`totals` 给一个跨桶总量（`积分剩 9226 / 12700`）。空分组（没买过加量包：容量 0、包数 0）不画成 0%，直接不列。
- **计费源优先读网关的结构化字段，显示名只是兜底**：`ai-shim` 的 `/v1/models` 每行带 `quota: {source, basis, backends}`（它按该行的 `backends` 判定「哪份订阅在扣」，见 `router/quota_source.py`）。Host 在同一次清单同步里把它收起来（模型条目本身装不下：`llm-pi-ai` 的 schema 不是我们的），随 `GET /dsh-turn-cost/models` 的 `quotaSources` 发给页面，页面按 **provider 路由**隔离缓存（同名 `deepseek-v4.1-flash` 在 OpenCode 与网关上是两份不同的订阅，串了就是错账）。判定顺序因此变成：网关的 `quota.source` → provider id 映射表 → 显示名首段。`quota.source` 为 `null` 是「已判定读不到」（`mixed` 多订阅行 / 后端没有额度接口），直接 `NO_SOURCE`，不再去名字里找证据——目录没加载、模型 id 刚出现时名字本来是空的，那时按名字判定就会误报「无额度可查」。
- **一次失败的循环会在 60 秒后自己再看一眼，且永远不会把循环卡死**：`sync.run` 是单飞的——一个永远不 settle 的承诺（凭据服务还没水化时 `credentials.resolve` 就可能这样）会变成之后**每一次**读的答案，清单与 `quotaSources` 一起冻在启动时那次失败上，直到进程重启。所以每轮都有 `CYCLE_TIMEOUT_MS`（90s）截止，超时按 `timeout` 记进 `last` 并清掉在飞的承诺；不健康的轮次再按 60s→120s→240s 封顶 5 分钟退避重试，成功即重置阶梯。启动竞态（凭据未就绪 → 匿名 401）因此一分钟内自愈，而不是等下一个十分钟周期。
- **`/dsh-turn-cost/models` 在 `webServer` 一到就登记，不等 `settings`**：这条路由只从 `inject(['settings'])` 里注册时，那一趟没跑就等于路径不存在——GET 走 SPA fallback 回 404，而同一插件的其它路由照常工作，页面只能把它报成错误（DSH 的 web 层对非 GET/HEAD 在匹配前统一回 405，所以「POST 有反应」不代表路由登记成功）。现在由 `createModelsSurface` 先占住路径，未挂载时回 200 + `syncUnavailable: true / reason: 'settings-unavailable'`（可诊断的空白，而不是 404），`settings` 到达后 `mountModelSync` 把同步循环接上去，`quotaSources` 从此有来源。
- **额度也可以由网关代读**：配了 `DSH_TURN_COST_GATEWAY_URL` 时 Host 先读 `GET /v1/quota?backend=<id>`（Bearer 用 `AI_ROUTER_API_KEY`，与 `ai-router` provider 同一把钥匙），把网关的每后端快照归一成同一 envelope（`via: 'gateway'`）；读不到（网关没这个后端、`supported:false`、HTTP 失败、无密钥）就**逐源回落**到原来的直连端点（`DEEPSEEK_API_KEY` / `OPENCODE_GO_API_KEY` / WorkBuddy shim 的 `/quota`）。这么做的理由是网关本来就持有 WorkBuddy 账号令牌、也本来就是这台机器唯一在说话的对端：本机不必再维护那条 shim 隧道，也不必为每种订阅各配一把供应商密钥；而回落保证网关抖动时卡片不会变白（只会退回旧行为）。
- **网关路由看模型显示名里的平台段**：`ai-router` 这类自建网关是多后端转发层，但它的每一行模型都**锁定单一后端**，而 `host/model-sync/naming.js` 正是把后端写进显示名首段——`<平台> · <计费> · <名字>[ · <窗口>]`。所以 `WorkBuddy · 付费 · DeepSeek-V4.1-Flash · 1M` 这一行确实由 WorkBuddy 账号付费，读 shim 的 `/quota` 是诚实的。判定顺序：provider id 命中映射表 → 显示名首段命中 `workbuddy` / `OpenCode Go` / `OpenCode Zen` → 有 provider 但都不命中则 `NO_SOURCE`。显示名从**输入框模型目录**（`modelDirectories` 服务的 `directoryFor(sessionId).store`，`models[].name`）取，对任意路由都查得到，不限于当前选中项。`platformOfLabel` 只把**首段**当平台：模型名里出现 "WorkBuddy" 字样的第三方模型不会被误判。
- **没有可读额度就不显示**：`OpenRouter` / `SiliconFlow` / `Gemini` / `NVIDIA NIM` 这类后端本插件读不到余量，落到 `NO_SOURCE`：不显示金额、不显示百分比、不算倒计时、**一次额度请求都不发**，只写一行「此供应商无额度可查」，悬浮补一句为什么。绝不借用 OpenCode 的窗口来顶替别人后端的花费。
- **`NO_SOURCE` 不进“记住的源”**：「这条路由没有可读额度」是某一段对话路由的事实，不是下一段对话的偏好。写进 `localStorage` 的只有真额度源；旧版本存下的 `none` 在读取时就被丢掉，否则每个空会话都会一开屏写「此供应商无额度可查」，哪怕输入框选的是可读的套餐。
- **只看主视图那一个会话**：额度回答的是「我正在看的这段对话在花哪份订阅」，所以只认 `retainedBy.mainView > 0` 的那一行，别的会话（后台子 agent、别的 workspace、已归档）再新也不能接管侧栏脚。
- **主视图没有会话就只认记住的源，绝不跨会话猜**：落地页 / 刚开新会话前 `currentSessionIdOf()` 返回 `null`，此时不推导任何源，直接写 `localStorage` 里记住的那个（首帧本来也按它着墨）。不这么做的代价实测过：多个会话并发（一份 `opencode-go`、一份 `ai-router` 上的 WorkBuddy）时「所有会话里时间戳最新的那条路由」每几秒换人，脚标就在 OpenCode 三条计量条和「此供应商无额度可查」之间反复跳——而且那条捷径没传模型显示名，网关路由一律被判成 `NO_SOURCE`。脚标属于整个 app，具体数字只属于一段对话；屏幕上没有对话，就没有比「上次看到的那个」更诚实的答案。
- **会话在跑时用正在跑的模型，跑完才用输入框选的模型**：判定来自 `modelSelection` 投影与 Session UI 状态（`useSessionStatus`）：
  - **运行中** → 取 `lastUsed`（上一笔真实请求用的路由），即 `activeRouteOfSession`。输入框里刚切成 OpenCode 只是**下一轮**的承诺，本轮还在 WorkBuddy 上烧积分，此时切源就会闪出 OpenCode 的窗口。
  - **等待你回答**（`pendingInteraction` 非空，含 DSH 的提问）→ **仍算运行中**。停下来提问不等于结束这一轮，也不是新一轮对话，同一路由继续在付费，所以继续显示正在跑的那份额度。
  - **空闲**（本轮结束、等下一轮或空会话）→ 取 `modelSelection.next ?? lastUsed`，即 `selectedRouteOfSession`：输入框选的那个模型，下一句话就要它付费。
  - 两条路径都回落到 `tcTimeline`（`current` / `requests` 末尾），用于投影还没到达的会话。
- **切源防抖 1.2 秒**：候选源在 `QUOTA_SOURCE_DEBOUNCE_MS`（1200ms）内被反复改写时不提交，只有活下来的那个才真正去读并落画。页面加载、重连、一轮结束这些时刻，会话列表、投影、状态帧是分几趟到达的，中间态都是「看起来像答案」的值——以前的 OpenCode 窗口闪现就是这个中间态被当成答案画了出来。硬约束：`read()` 是 `useSyncExternalStore` 的 `getSnapshot`，**必须引用稳定**，所以只在 `schedule()` 里推进提交值；`null`（无源）与首次落画都立即提交，因为此时没有数字要保、也就没有闪烁可防。首帧只按「记住的源」着墨，绝不采纳可能处于中间态的候选。
- **无源时留白**：拿不到 provider 也没有上次记忆时，卡片**不显示任何数字**（状态 `idle`，`refresh` 直接返回，不读任何源）。这是刻意的——以前路由参数默认 `deepseek`，刷新页面会在会话自己的路由还没到达前先画一次 DeepSeek 钱包，OpenCode 订阅的账户就看到了「DeepSeek 官方额度」。
- **两种「不显示」要分清**：`idle` = 还不知道（等会话路由），`nostore` = 已经知道，且该 provider 本来就没有额度。前者悬浮只有标题，后者给出原因；`NO_SOURCE` 也会被记忆，所以新开空会话仍然不会回落到别的套餐。
- **记住上次的源**：认出的源写进 `localStorage` 的 `dsh-turn-cost:quota-source`，新开空会话或刷新时先按它显示，等会话自己的路由到达再覆盖。
- **第一行**：`用量总览` + 右侧倒计时徽标（`剩 12 天`）。倒计时取**最长额度窗口的重置时刻**——OpenCode Go 的月窗口重置即订阅周期结束，官方 `usage` 接口除这三个窗口的重置时间外不给到期字段，所以周期长度由此推出；不满 1 天给小时、不满 1 小时给分钟，过点写「已到期」。≤7 天转黄、≤3 天转红。悬浮徽标给出确定的日期时刻（如「订阅周期 12-02 23:30 结束（剩 12 天）」）。
- **第二行（OpenCode Go）**：5 小时 / 周 / 月三条**微型计量条**——标签 + 百分比 + 3px 轨道，填充按百分比给长度，≥70% 转黄、≥90% 转红，一眼看出哪档先见底。整卡悬浮给三档全称、百分比、**北京时间重置时间与各档自己的倒计时**（如「本周：已用 37%，11-23 08:00 重置（剩 2 天）」）。侧栏折叠成 36px 导轨时整卡收成一枚小方块：最紧那档的百分比 + 紧凑倒计时（`54%` / `12天`）。
- **仪表盘磁贴**：标题写「OpenCode Go 额度」，主数字是最紧的那档（`月 54%`），副行给倒计时与读取时刻（`剩 12 天 · 23:21 更新`）；三档全量在悬浮明细里。
- **DeepSeek**：官方 `GET https://api.deepseek.com/user/balance`，取每币种 `total_balance` 并保留 `topped_up_balance` / `granted_balance` 拆项。第二行是 `¥19.75`（无周期可算，只有钱包）；悬浮给充值 / 赠送拆项；磁贴同源。
- **先画上次读数，再静默刷新**：每次读数成功都按源写进 `localStorage` 的 `dsh-turn-cost:quota-cache`（`{source:{at,snapshot}}`），下次加载（刷新页面、chunk 重新加载、开新会话）先按它把上次的数字画上去，**不发「读取中…」**，同时在后台静默读一次；只有这个源**从来没有过读数**时才显示「读取中…」。缓存的有效期取 5 小时（最短的 5 小时窗口一个周期内必然已重置，更久的百分比描述的是已经结束的周期），并且**任一窗口的重置时刻已过就整条作废**——把上个周期的 47% 画到新周期上比转圈更误导。带过来／刷新失败的数字会降透明度并在悬浮里注明「显示的是上次成功读数，正在后台重试」，不再整卡变成「额度不可用」；`failed` / `loading` / `nostore` / 零余额一律不写缓存。
- **什么时候再读**：客户端每 5 分钟轮询一次；另外标签页从后台回到前台（`visibilitychange` → `visible`）和网络恢复（`online`）各补读一次，避免挂机几小时后看到的还是几小时前的数。这次补读不带 `force`，仍在 Host 的 5 分钟新鲜期内就直接用缓存，不打厂商接口。
- **数据流**：Client 只请求同源路由 `GET /dsh-turn-cost/quota?source=<id>`（每 5 分钟一次，点按带 `force=1`）。Host 的 `host/quota.js` 才持有密钥（`credentials` 里的 `DEEPSEEK_API_KEY` / `OPENCODE_GO_API_KEY`，每次读取时解析，不缓存）、发官方请求（OpenCode 每次请求现造 `x-opencode-session` / `x-opencode-request`，12s 超时）、按源缓存 5 分钟。**密钥与官方原始 payload 都不进页面**。
- **异常分支**：读失败（网络、超时、非 2xx）→「额度不可用」；Host 未配置该源密钥 →「未配置密钥」；余额/窗口为 0 →「零余额」。三者都不伪装成 0 消耗。失败不写缓存，下一次轮询／点按会重试；缓存里的上一次成功值继续服务非强制读。
- **无源分支**：既没有会话路由也没有记忆 → 卡片只有标题与按钮，不显示金额、不显示百分比、不发请求。
- **失败是安全的**：Host 没有 `webServer` 或 `credentials` 时不会注册路由，按钮退回普通样式（首读失败即静默），费用与上下文功能完全不受影响。未知 `source` 参数由 Host 直接 400，不会悄悄给成默认源。

## 模型清单自动同步（自建网关）

DSH 只给 **pi-ai 内置目录里的** provider 路由准备运行时模型目录；`ai-router` 这类自建网关不在目录里，于是 profile 里 `models` 声明的那份清单**就是**模型选择器——网关上新了模型、下线了模型、改了上下文窗口，都不会自己出现。设置页的「获取可用模型」能拉一次，但它只把候选递进表单（`id / name / 上下文 / 输出上限`），模态与思考档位会丢，而且要手点保存。

本插件把这一步自动化：

- **查看即读，读即核对**：「设置 → 模型目录」这一页和设置面板头部的模型 chip 一出现，就先画上次的清单（Host 里已存的 profile 清单 + 本浏览器上次的快照），再让 Host 在后台核对一次网关；核对回来的新清单在下一帧静默换上，这一轮新出现的模型标「新增」。你永远不用等网关。
- 每次打开设置都会触发一次核对（chip 挂在面板头部，所以直接去 DSH 原生的模型页也算），但同一个 `staleMs`（默认 5 分钟）窗口内只核对一次；另有启动后 20 秒 + 每 10 分钟一轮的兜底轮询。
- 核对时逐行生成条目：显示名 `<平台> · <计费> · <名字> · <窗口>`（多供应商自动降级的行写成 `<名字> · <计费>自动降级`）、`input` 模态、`contextWindow` / `maxTokens`、`reasoningEfforts` 与 `effective` 所需的两个 compat 开关；条目上本模块不拥有的字段（例如手动加的请求级图片限额）原样保留。
- 与 profile 里已存的清单**逐条比较**，只有真的不一致才写回；写回走 DSH 的 `settings` 服务（校验条目 → 落盘 profile → 重建 provider 一个事务），所以不打补丁、不改 `node_modules`、不手写 `cordis.patch.yml`。
- 三种情况一个字都不写，保持旧清单：清单拉不到（超时 / 非 2xx / 不是 JSON / 超大）、清单为空、生成的显示名越界（含 router 历史标记 `· Trae` / `· 付费源待命`）。
- 行上没有声明的能力不补不猜：`input` 缺省仍是 `["text"]`，思考档位缺省就不写——把文本模型标成收图会在消息落盘后才被上游拒，比提前拦下更糟。
- 手改过的 `reasoningEfforts`（出现非 canonical 键、或 wire 值与档位不等）视为用户所有：整块保留，同步只刷新它自己生成的字段。

状态与手动触发（同一 Host；不带 `force=1` 时立即回缓存、只在后台核对）：

```bash
curl -s http://127.0.0.1:3080/dsh-turn-cost/models | jq .last
curl -s 'http://127.0.0.1:3080/dsh-turn-cost/models?force=1' | jq .last
```

关掉/改频率见 README 的环境变量表。**在设置页保存过模型卡之后**（它会把上游 `name` 回写、并按表单重建条目），下一轮同步会把显示名与能力补回来——这段时间里选择器可能短暂显示朴素名字。

## 项目记忆（同一个包里的另一半边）

这一半来自原 `dsh-project-memory`，现在不是独立插件行，而是由 `index.js` 挂载的库 + 第三个懒加载 chunk + 随包 skill。它与会话成本**没有调用关系**：两半各自 try/catch 挂载，记忆引擎崩了照常算钱，额度路由挂了照常用记忆。

- **存三样东西**（项目根的 `.dsh-project-memory/`，`memoryDir` 可改）：
  - **索引语料**：项目自己的 Markdown / PDF / 文本（`indexDocs: true` 时；`AGENTS.md`、`docs/` 里的规范与风格文档按 3000 字切块，标题命中 必须/禁止/规则/约定/清单 等规范词在 doc 层 ×1.5 提权）+ 代码符号（JS/TS、Python、Go、Rust、C 族、Shell 六类，按声明行提取），每条带 `path:line` 引用。doc 层不参与每步静默注入，只服务 `query_memory`。索引期**零 LLM 调用**，分块默认 3000 字符、单文件上限 40 块、单文件内存闸门 10 MB（峰值 RSS 约为磁盘的 10–22 倍，闸门挡的是整文件物化的那一下）。
  - **经验条目**：`lesson`（问题 → 修法）、`decision`（选了什么 + 为什么）、`procedure`（步骤）、`experience`（记录）。写入侧按重叠度去重、按置信度强化/提升（项目级超 `maxProject` 才归档），全局文件单独一份。
  - **任务**：跨会话工作记录（步骤 + 热文件），会话可绑定到一条；绑定后按 `tasklist.syncHostOnAdopt` 把它推成宿主 todo 快照。
- **9 个工具**：`list_tasks` / `select_task` / `archive_task` / `show_task_panel` / `query_memory` / `remember` / `forget` / `save_lesson` / `pm_stats`（`index_doc` / `index_repo` / `watch_repo` 仅在 `corpusEnabled: true` 时注册；默认 false —— 代码结构归 codegraph、笔记语料归 `search_notes`）。逐个注册：某个名字被别的插件占了只丢那一个，并在 `ctx.logger` 里点名（这条日志是"插件装了但工具全没了"的唯一线索）。
- **唯一命令 `/tasks`**：裸 `/tasks` 给任务清单快照；`/tasks switch|archive|unbind|rename|todos …` 与 `/tasks insight list|confirm|promote|…` 是子动词，主要由面板按钮经 `remote.commands.execute` 驱动。它**不声明 `input`**，所以手敲 `/tasks` 回车立刻执行（代价是带参数的行不再被认成命令，那些入口本来就在按钮上）。
- **每步静默注入**：`agent/pre-step` 时在请求前追加一条记忆消息——「entry 常驻块」（最近任务与高置信经验，默认最多 6 条 / 400 token）+ 按当前提示相关性门控的条目。同一条正文没变就不重发；单会话保险丝 60 条 / 24000 字符；`auditLog` / `shadowLog` 只写盘不进 prompt（影子日志每步一行，含全部候选判据，为的是能离线重放"换个阈值会怎样"）。无项目 root 可解析时零副作用。

- **界面**（懒加载 chunk `client.memory.js`，源码 `client-memory-src/`）：任务面板（`shell.overlay` 浮层：任务页 / 记忆页 / 新建表单 / 分页 / 拖拽）、`/tasks` 的命令节点（接管内置的大段文本卡片，避免 JSON 载荷刷屏）、`show_task_panel` 的工具视图（结果一渲染就开面板——面板状态只在浏览器侧，宿主碰不到）、`/` 菜单的「工作流」组（纯客户端开面板页，不发宿主命令）、「设置 → 记忆与笔记」页（只剩**笔记检索三项**：仓库入口 / 启用开关 / 单次超时，见下节）。

## 笔记检索（`search_notes`）

同一个包里的第三条能力：`search_notes` 工具。内核仍是笔记仓库里的 `search_core.py`（section 级 BM25F + 语义 RRF 融合 + 中文别名 + 相关性策略），这里只做桥——一条 JSON 进、一条 JSON 出，检索语义永远和 CLI 同一份实现；`host/notes/bridge.py` 是常驻子进程，行分隔 JSON 协议。

- **在哪配**：`设置 → 记忆与笔记 → 笔记检索`
  - **笔记目录**：含 `.notes/` 的仓库根（如 `~/note`）。**留空 = 不启用**：宿主不拉进程，工具如实报「未配置」并指名这一处。
    字段本身是**选择器**，不是输入框：点「选择目录」→ 先探测宿主装配了哪种目录选择能力（`uiWorkspace` / `remote.directoryPicker` 的 `list` 动词能不能用），`native` 装配弹操作系统自己的文件夹对话框，`browse` 装配弹站内目录树（面包屑下钻、只列目录、确认写回绝对路径）；探测结论按会话缓存，一次失败 RPC 之后不再重复。两种能力都没有（老宿主）才退回手写输入框，「手动输入」链接给 `~/note` 这类写法留一条路。
  - **启用笔记检索**：关掉后模型侧不再有可用入口，路径保留，改回来即恢复。
  - **单次检索超时**：默认 30000 ms。首查要加载语义模型（实测 1–6 秒），之后 200–400 ms。
  - 三个字段都是 **volatile**：保存即生效，目录一变就 dispose 旧进程、按需拉起新进程，不用重启会话。解释器（`notes.python`，空 = 优先仓库自带 venv）与预热（`notes.warmup`）只留在 profile，界面不暴露。
- **工具恒在**：`search_notes` 不再「配置了才注册」。没配置时它也出现在工具表里，调用会失败并给出可执行的一句话（去哪个设置页填哪个格子）——能力不该靠"界面上没有痕迹"来隐身。
- **失败不装成空结果**：空结果与"没装好"在模型眼里长得一样，一旦混同，模型会把换词搜索变成空转。所以报错如实抛出，并回传 `mode=hybrid|degraded`、`semantic`、`relevance`；降级时明说「仅词面检索」及原因。
- **与项目记忆的分工**：笔记仓（`~/note`）的 Markdown 只由这条通道提供；项目自己的 `AGENTS.md` / `docs/`（架构、设计、风格）归记忆库的 doc 层（`indexDocs: true` 时按 3000 字切块入库，标题命中规范词 ×1.5 提权），两条通道的路径不重叠。记忆根恰好是笔记仓自身时打开 doc 层会出现重复命中——那里的检索应走 `search_notes`。

## 偏好设置

`设置 → 费用`（插件自有页面，带 ¥ 图标）分组呈现：

- **显示**：逐轮费用徽章（开关）、底部会话累计（开关）
- **计价**：金额币种（人民币 / 美元分段控件）、DeepSeek 计费时段（自动按北京时间 / 按高峰 / 按空闲）
- **预算**：会话预算（0 = 不设上限，正数 = 显示 花费/预算 并在超支转红）
- 重置偏好

偏好存在浏览器 `localStorage`（键 `dsh-turn-cost:prefs`），不写 Host 配置，也不影响其他客户端。切换币种立即作用于所有金额界面。

## 价格来自哪里

价格表写在 `client.js` 的 `OFFICIAL` 常量中，单位为 **USD / 1,000,000 tokens**，均于 **2026-11-15（GMT+8）** 从各家**官方**价目页核对：

- DeepSeek：<https://api-docs.deepseek.com/quick_start/pricing>（另有官方人民币价 <https://api-docs.deepseek.com/zh-cn/quick_start/pricing>）
- Anthropic：<https://docs.anthropic.com/en/docs/about-claude/pricing>
- OpenAI：<https://platform.openai.com/docs/pricing>
- Google Gemini：<https://ai.google.dev/gemini-api/docs/pricing>

详见 [PRICING.md](PRICING.md)。本插件**不使用** models.dev、pi-ai catalog 等第三方聚合价格。

人民币显示有两条来源，优先级固定：**厂商自己发布人民币刊例价的**（DeepSeek）直接用官方人民币价；**只发布美元价的**（Anthropic / OpenAI / Google）按 `client.js#USD_TO_CNY`（7.2）折算，并在明细里显式标注这是汇率折算、不是厂商人民币价。

## 计算口径

- 用量直接取 DSH 自带的 `deriveTurnTokenUsage()` 结果（`turn-tail` 节点的 `tokenUsage`），包含重试与失败 attempt，精确到 token；本插件不重算会话日志。
- 四个桶分别按各自的官方单价计价；每桶金额由 `桶数量 × 显示币种单价` 得出，徽章明细、Token 统计、费用构成三处用的是同一份数。
- **DeepSeek 高峰/空闲**：官方规定北京时间周一至周五 09:00–12:00、14:00–18:00 为高峰（不含中国法定节假日），空闲价为高峰价一半。会话内的每一笔请求按它自己的时间判档（徽章、药丸、费用卡、逐请求浏览器都如此）；仪表盘是跨会话的按天聚合、请求时间不再保留，所以 Host 在折叠时就把每笔请求分进 `peakBuckets` / `offPeakBuckets`，仪表盘按桶分别计价，历史金额不会被「现在几点」改写。`HOLIDAYS_UTC8`（Host 侧同名常量 `BEIJING_HOLIDAYS`）可按需补充，两处需同时改。
- 一輪若用了多个模型，聚合用量无法按模型拆分：按首个模型计价并用 `≈` 标记。
- 部分 attempt 未上报缓存桶时，未归属的提示词按缓存命中单价计（保守下界），同样用 `≈` 标记。
- 经由网关（`ai-router` / `opencode-go` 等）调用时，官方模型常以版本名出现（如 `deepseek-v4.1-flash`）。插件把官方文档明确认定为同一模型的别名映射到官方价格行；详情里会说明这是**按官方刊例价估算，非实际扣费**。
- 提供方明确标注免费的模型显示 `¥0 · 免费`；价格表未收录的模型显示「价格未知」，**不会**按 `0` 计。会话累计会注明有多少请求未计入。
- 币种只影响显示：`usd` / `cny` 两份金额始终同时保留。

## 视觉约定

所有界面只用宿主语义 token（`--dsw-alias-*` / `--dsw-font-*` / `--dsw-radius-*` / `--dsw-elevation-*`），不写死颜色，浅色与深色主题都成立。数据色用宿主的 `--dsw-alias-chart-system / chart-tools / chart-messages` 与 `state-*`。分段控件的选中态用 `--dsw-alias-button-primary-fill` + `--dsw-alias-label-primary-foreground` —— 不要用 `--dsw-alias-brand-primary`（深色主题里它是近白色 `#f9fafb`，会造成白底白字）。

## 不包含

- 子 Agent 会话的费用（只统计当前会话的轮次；仪表盘按会话聚合时也只读各会话自己的日志）。
- 联网搜索 / 文件解析 / OCR / TTS 等按次计费项。
- Batch / Flex / Priority 等非标准计费档；一律按 Standard 同步档。
- 网关/转售商（OpenRouter、Groq 等）的价格：没有单一第一方刊例价。

## 价格过期怎么办

官方价目会变。更新 `client.js` 顶部 `OFFICIAL` 表中对应模型的数字，并同步修改 `docs/PRICING.md` 的核对日期与徽章明细里的 `date`（`client.js` 中 `t('source', { date: ... })`）。修改后刷新页面即可生效（无需重启 DSH）。

> 改了 `client.context.js` 记得 `touch client.js`：Host 只监听入口文件，静态包按 rev（mtime）作 URL，rev 不变浏览器会继续用 `immutable` 缓存的旧 chunk。
